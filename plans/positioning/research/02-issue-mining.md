# 02 · Issue-tracker mining: unmet needs across self-hosted photo managers

Collected 2026-10-16 with the `gh` CLI (read-only: no comments, reactions or new issues).
Repos: [immich-app/immich](https://github.com/immich-app/immich), [photoprism/photoprism](https://github.com/photoprism/photoprism), [ente/ente](https://github.com/ente/ente) (formerly `ente-io/ente`), [pulsejet/memories](https://github.com/pulsejet/memories) (the brief said `nextcloud/memories`, which does not exist; Nextcloud Memories lives at `pulsejet/memories`), [LibrePhotos/librephotos](https://github.com/LibrePhotos/librephotos).

Files next to this one:

- `02-issues.csv`: 553 rows, one per issue/discussion: repo, type (`open` / `declined` / `declined?` / `gated`), kind (feature/bug/tech-debt), cluster, reactions, title, url, created, labels, source, state_reason. 541 rows count as demand; the 12 `gated` rows are PhotoPrism paid-tier context.
- `02-raw/*.json`: the raw query results (titles, urls, 👍, labels, the first 600 characters of the body). `02-raw/normalized.json` is the CSV as JSON. `02-raw/cluster-snippets.md` is the generated cluster table. `02-raw/docs/` holds the competitor docs quoted below (Immich FAQ, PhotoPrism docs).
- Scripts: `fetch_issues.py` (collection), `build_dataset.py` (normalising plus keyword rules and per-URL overrides for clustering), `snippets.py` (tables).

LibrePhotos evidence links point at commit [`9f71dd42`](https://github.com/LibrePhotos/librephotos/tree/9f71dd4258dff2f0d147d262c8063045677a6469) (on `dev`, 2026-10-15). Many of the features cited there are **in `dev` but not released yet** (after 1.3.0); the docs mark them "Not released yet", and this report flags them as *(dev)*.

**How to read the low ranks.** Clusters 10 (metadata in files) and 16 (folders as truth) look small in reactions but large in the competitors' *own docs*. Immich states the limits as policy, not as open requests, so users have little to upvote:

- Immich FAQ: "No, Immich does not modify the original files. All edited metadata is saved in companion `.xmp` sidecar files and the database." ([FAQ.mdx](https://github.com/immich-app/immich/blob/main/docs/docs/FAQ.mdx), copy in `02-raw/docs/immich-FAQ.mdx`, line 109)
- The same FAQ says metadata "cannot be edited for files in read-only external libraries" (line 258; bug [immich#10538](https://github.com/immich-app/immich/issues/10538), 28 👍, silent failure). It says there is no official way to create albums from external-library folders (line 248, pointing at [d4279](https://github.com/immich-app/immich/discussions/4279), 211). And duplicate checking "is not global, but _per library_" (line 252).

Taken together, "my files and folders are the source of truth" (clusters 10, 13 from folders, 16, and part of 7) adds up to about **1,000** reactions, which would rank around #4.

### 3c. PhotoPrism: needs behind a paid tier

Evidence comes from PhotoPrism's own docs ([roles.md](https://github.com/photoprism/photoprism-docs/blob/develop/docs/user-guide/users/roles.md), [getting-started/faq.md](https://github.com/photoprism/photoprism-docs/blob/develop/docs/getting-started/faq.md), copies in `02-raw/docs/`) and the issue labels:

- **Multi-user roles**: the docs say "*User* and *Viewer* are available with Essentials and Plus; our Community Edition provides *Admin*, *Guest*, and *Visitor*." Even then, *Users* "have full access to the library" (one shared library), so per-user private libraries ([#98](https://github.com/photoprism/photoprism/issues/98), 610) are missing from every edition.
- **LDAP / Active Directory**: Pro edition only (faq.md line 568; [#484](https://github.com/photoprism/photoprism/issues/484), label `pro-feature`). OIDC is in all editions.
- **Satellite / outdoor / 3D maps**: members only (faq.md line 102; [#3455](https://github.com/photoprism/photoprism/issues/3455) `member-feature`).
- **Custom themes** [#1763](https://github.com/photoprism/photoprism/issues/1763) (`pro-feature`); the dark theme [#700](https://github.com/photoprism/photoprism/issues/700) and the Electra theme [#2916](https://github.com/photoprism/photoprism/issues/2916) (`member-feature`); **SVG/EPS vector graphics** [#2207](https://github.com/photoprism/photoprism/issues/2207) (`plus-feature`); **OpenTelemetry** [#5382](https://github.com/photoprism/photoprism/issues/5382) and Entra ID groups [#5334](https://github.com/photoprism/photoprism/issues/5334) (`pro-feature`).
- The Docker image ships under the "Plus License", while the source build is AGPL "except additional user roles" (faq.md lines 244 and 317).

LibrePhotos is AGPL with no paid tier, so multi-user with **private per-user libraries** is free ([managing-users.md](https://github.com/LibrePhotos/librephotos/blob/9f71dd4258dff2f0d147d262c8063045677a6469/apps/docs/docs/user-guide/managing-users.md): a per-user scan directory, scan directories cannot overlap).

## 6. Limits

- **Reaction counts favour old items.** For example, [pp#47](https://github.com/photoprism/photoprism/issues/47) dates from 2018 and [pp#98](https://github.com/photoprism/photoprism/issues/98) from 2019, while new requests have had little time to collect votes. Nothing is normalised by age; the `created` column in the CSV allows it.
- **Issues and Discussions are mixed.** Immich moved feature requests to Discussions, so its open *issues* are mostly bugs and its demand is in upvotes. Ente and PhotoPrism use both. Upvotes and 👍 are different counters; the sums only rank, they do not measure.
- **Duplicates are folded away.** Immich closed 2,694 Feature Request discussions as DUPLICATE; their votes stay on the closed copies and are not counted. Real demand for popular asks is therefore higher than shown.
- **"Declined" is noisy.** `not planned` also covers stale and invalid bugs (e.g. most of Ente's 105). Immich OUTDATED discussions are labelled `declined?` because some were overtaken by other work: OCR [#565](https://github.com/immich-app/immich/issues/565) was "not planned" in 2022 and was built later. Immich RESOLVED discussions (1,276) were left out as "probably built", but some may have been closed with a refusal; comments were not read.
- **Some declines are invisible to reaction searches.** Several of the most important ones are written as policy in docs (Immich FAQ, PhotoPrism editions), not as closed issues; §3 cites them directly.
- **The clustering is a heuristic** (title regexes plus about 200 hand overrides in `build_dataset.py`) and is not exhaustive. An item has one cluster even when it spans two (e.g. [d4279](https://github.com/immich-app/immich/discussions/4279) is both "smart albums" and "folders as truth"). `kind` (feature/bug) is a title heuristic.
- **The sample is capped**: top 50 open and top 30 declined per source. The long tail is not covered.
- **Repo naming.** The search API refused `repo:ente-io/ente`, because the repo was renamed to `ente/ente`; Ente's open and not-planned sets were pulled via GraphQL over all issues and match a later `repo:ente/ente` search (188 open). `nextcloud/memories` does not exist, so `pulsejet/memories` was used.
- **LibrePhotos status comes from docs and code at `9f71dd42` (dev).** Many items are *(dev)* and unreleased; a user on 1.3.0 does not have them yet. None of the statuses were checked in a running app, and "partial / no" rests on doc reading and grep hits (a missing grep hit is weaker evidence than a doc statement).
- **PhotoPrism gating** comes only from its public docs and three labels; the editions comparison page on photoprism.app was not fetched.
