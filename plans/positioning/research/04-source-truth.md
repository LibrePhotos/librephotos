## Headline findings

1. **Native Windows is a unique LibrePhotos claim, and it is real.** Each release since 1.2.0 attaches a ~450 MB
   Nuitka zip built by CI on `windows-latest`. None of the four others has a non-Docker Windows server path.
2. **Write-back: LibrePhotos is the only one that writes face regions, and the only one that lets the user
   choose original vs sidecar.** But it is off by default, and in the released 1.3.0 it covers only rating, date,
   rotation and faces. Captions, keywords and GPS write-back (and the #2690 "Write metadata to files" job) exist
   only on `dev`. Immich writes more fields by default (description, rating, date, GPS, tags), but only to
   `.xmp` sidecars. It never writes favourites or faces.
3. **Delete semantics are the sharpest folder-as-truth difference.** All three server apps delete originals
   from disk when you permanently delete. Immich does it for external libraries too, and its 30-day trash expiry
   is **on** by default. LibrePhotos' auto-expiry defaults to 0 (off). PhotoPrism has a real read-only mode in
   code. Immich and LibrePhotos rely on a `:ro` mount.
4. **ML footprint:** Immich is the only one that needs a separate ML container and declares the highest RAM
   floor (6 GB). LibrePhotos and PhotoPrism run ONNX in the app container. LibrePhotos' default stack includes
   a local VLM captioner (LFM2.5-VL-450M), which no competitor runs by default.
5. **Paywall:** PhotoPrism is the only one with real feature gates in its open-source edition: multi-user
   management, roles, SVG and map styles. Immich's key is cosmetic. Ente self-host caps users at 10 GB until an
   admin runs the CLI. LibrePhotos and Memories have none.

## Surprises (code vs docs or expectations)

- **LibrePhotos:** the docs on `dev` describe caption/keyword/GPS write-back and the write-metadata job, but
  released 1.3.0 does not have them. A benchmark pinned to 1.3.0 will show "no" for caption/keyword
  round-trip. Any positioning copy has to say "from 1.4.0".
- **Immich:** the FAQ says "does not modify the original files", yet it deletes external-library originals on
  trash expiry by default. Sidecar write failures (for example on a `:ro` mount) are only logged, and the edit is
  then re-read from the unchanged file. Downloads leave out the `.xmp`, so edits do not travel with an export.
- **PhotoPrism:** NASNet/FaceNet are gone (ONNX EfficientFormerV2 + SFace). There is no star rating at
  all. "Never modifies originals" is not strict: rotating rewrites EXIF Orientation in the original JPEG/PNG.
  The CE admin UI is a stub, and CE can only assign admin/guest/visitor roles. The default image tag is not
  the `-ce` build: Docker Hub has separate `261007` and `261007-ce` tags.
- **Ente:** paid-only gates are bypassed on self-host by an "is there a user with id 1" heuristic, yet the
  10 GB free quota still applies. `RUNNING.md` says "static Go binary", but the code uses Unix-only syscalls.
- **Memories:** the canonical repo is `pulsejet/memories`, not `nextcloud/memories`. The FAQ says no XMP
  support, but it writes Title/Description/Label/date/GPS straight into originals with
  `-overwrite_original_in_place`. v10.1.0 ships an undocumented "Lens" Python ML daemon (torch,
  SigLIP2, Qdrant). The install docs list PHP 8.0/NC 26, while `info.xml` requires PHP 8.3/NC 34-35.
