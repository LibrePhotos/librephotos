LibrePhotos switched to semantic versioning: the release after 2026w25 is **1.0.0**, and releases are numbered from now on instead of being named after the week. 1.0.1, 1.0.2 and 1.0.3 followed within two days with small fixes. This post collects all four.

**Upstream:**

🚀 LibrePhotos: Switching to Semantic Versioning

1.0.0 is the first numbered release. Next to the new version scheme, it carries the fixes merged since 2026w25:

- 🔨 Backend: Clear the old 128-dim face encodings in migration 0126 with a set-based UPDATE ([#1872](https://github.com/LibrePhotos/librephotos/pull/1872)) (Implemented by [dotanm](https://github.com/dotanm))
- 🔨 Backend: Harden metadata reading against transient exif-service failures ([#1873](https://github.com/LibrePhotos/librephotos/pull/1873)) (Implemented by [dotanm](https://github.com/dotanm))
- 🔨 Backend: Retry transient face-service connection drops ([#1874](https://github.com/LibrePhotos/librephotos/pull/1874)) (Implemented by [dotanm](https://github.com/dotanm))
- 🔨 Backend: Keep the latest finished job per type when old jobs are cleaned up, so the scan keeps its baseline ([#1875](https://github.com/LibrePhotos/librephotos/pull/1875)) (Implemented by [dotanm](https://github.com/dotanm))
- 🔨 Backend: Numeric EXIF tag values are read as text in the date-time extractor ([#1879](https://github.com/LibrePhotos/librephotos/pull/1879)) (Implemented by [dotanm](https://github.com/dotanm))
- ✨ Backend: PyExifTool is pinned to 0.4.9 ([#1882](https://github.com/LibrePhotos/librephotos/pull/1882)), and the backend dependencies are updated ([#1877](https://github.com/LibrePhotos/librephotos/pull/1877))
- 🔒 Frontend: Security updates for `@babel/runtime` 7.26.10 ([#1820](https://github.com/LibrePhotos/librephotos/pull/1820)) and `lodash` 4.18.1 ([#1821](https://github.com/LibrePhotos/librephotos/pull/1821))

**1.0.1 and 1.0.2:**

- 🔨 LibrePhotos: Fix the GPU backend image (`image-backend-gpu`)

**1.0.3:**

- 🔨 Frontend: Non-admin users no longer see a flood of "Required at results.N.…" popups on the main page ([#1888](https://github.com/LibrePhotos/librephotos/issues/1888), [#1889](https://github.com/LibrePhotos/librephotos/pull/1889)). The user list is now validated leniently, and the non-sensitive `public_sharing` flag is back in the public user serializer so the public-user discovery page keeps working. Sensitive fields (email, scan directory, Nextcloud credentials, superuser flag) remain hidden.

**Full changelog:** https://github.com/LibrePhotos/librephotos/compare/2026w25...1.0.3
