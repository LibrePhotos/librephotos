This release adds a **timeline filter** that keeps screenshots and documents out of the way, makes **videos play in every browser**, makes **search, the API and scans a lot faster on less memory**, and fixes a set of **reported security issues, including two code execution bugs**.

**Who should update:** Everyone. If other people use your LibrePhotos, or you share public links, update right away: this release fixes security problems.

**What's new for you:**

- Use the new **Filter** button on the timeline to hide screenshots and documents, or show only videos or favorites. **Save as default** keeps your choice.
- Videos that did not play in your browser before now play, for example iPhone videos in Firefox.
- If a photo is marked as a screenshot or document by mistake, fix it with the badge in the photo details.
- Search, scans and the app are faster and need less memory.

**After you update:**

- **Nothing to do for search and tags.** After the update, LibrePhotos reads every photo again in the background so that tags and search use the new model. Search finds more photos while this runs, and the **Things** albums fill up again. You can follow it under **Account menu > My Jobs**.
- **Admins: remove photo details from old thumbnails once. Recommended for everyone, required if you use public links.** Thumbnails made before 1.3.0 still contain the location and camera details of the photo, and public links show those thumbnails. One cleanup removes that data. Your photos and the thumbnails' pictures stay as they are, and running it twice does no harm.
  - **Windows app:** open the folder that contains `librephotos.exe`. Click the address bar of the folder window, type `cmd` and press Enter. In the black window, paste `start /wait librephotos.exe manage strip_thumbnail_metadata` and press Enter. If you start LibrePhotos with `--data-dir`, put the same `--data-dir <folder>` right after `librephotos.exe`. It is done when the window shows the prompt again.
  - **Docker:** in the folder with your `docker-compose.yml`, run `docker compose exec backend python manage.py strip_thumbnail_metadata`. Single container: `docker exec librephotos python manage.py strip_thumbnail_metadata`.
  - More detail: [After upgrading from 1.2.1 or older](https://docs.librephotos.com/docs/installation/upgrading#strip-thumbnail-metadata).
- <details><summary>Kubernetes</summary>The manifests in deploy/k8s now use 1.3.0 and PostgreSQL 16 instead of 2023w31 and PostgreSQL 13. Read the <a href="https://github.com/LibrePhotos/librephotos/tree/dev/deploy/k8s">Kubernetes README</a> before you apply them to an existing install.</details>

**Upstream:**

🚀 LibrePhotos: One Open Model for Tags and Search

Tags, semantic search, and similar photos now all come from **OpenCLIP ViT-B/32**, trained by LAION on DataComp-XL and released under the MIT licence. It replaces CLIP ViT-B/32 for search and the separate tagging model, so a scan runs one vision model per photo: tagging a photo produces its search embedding in the same pass. The separate `clip_embeddings` service is gone, and so are the model choices in the site settings, because there is nothing left to choose. Captions (LFM2.5-VL) and faces (InsightFace) are unchanged. See [Semantic search](https://docs.librephotos.com/docs/user-guide/search).

🚀 LibrePhotos: Faster Search, API, and Scans on Less Memory

The Rust and TypeScript backend experiments were much faster than Django, and most of the difference turned out to be queries, app-layer work, and ML memory rather than the language. Every optimization that applies to Django is now in LibrePhotos. On a 50,000 photo library, text search takes about half the time (1.19 s down to 0.56 s), album lists, the date list, user details, site settings, and thumbnails answer faster with fewer queries, and duplicate detection finishes in 27 seconds instead of running for hours. The idle API server uses about half the memory and starts in 3 seconds, heavy libraries load only when they are needed, and a scan with machine learning committed 2.25 GB instead of 10.7 GB in our test.

🚀 LibrePhotos: Timeline Filter and Category Correction

The timeline has a **Filter** button: show photos, videos, or both, hide screenshots, hide documents, or show only favorites, and **Save as default** to make that your timeline ([#2130](https://github.com/LibrePhotos/librephotos/issues/2130)). Select all acts on exactly what the timeline shows. When the automatic detection gets a photo wrong, fix its category in the lightbox (a badge says whether it was detected or set by you, with Undo) or mark a whole selection as photo, screenshot, or document from the selection menu. The sidebar is tidier too: Memories now appear as a strip on top of the timeline, the organizing pages moved into the Photos menu, and background jobs show as a progress ring around your avatar.

🚀 LibrePhotos: Videos That Play in Every Browser

Each video is now probed once during the scan, and its codec, pixel format, and colour transfer are stored. The web app uses that to ask the browser whether it can play the file, and converts only the videos it cannot play (for example HEVC in Firefox), instead of leaving "Always transcode videos" as the only way to play them ([#477](https://github.com/LibrePhotos/librephotos/issues/477), [#714](https://github.com/LibrePhotos/librephotos/issues/714)). HDR videos get an HDR badge on their tiles and correctly tonemapped thumbnails, and a **Probe Videos** job fills in videos scanned before this release. (Implemented by [dotanm](https://github.com/dotanm))

🚀 LibrePhotos: Security Fixes

This release fixes several reported vulnerabilities, so please upgrade. A person name containing a line break could inject options into ExifTool when face tags were written to files, which let a logged-in user run code on the server ([GHSA-x465-w9j9-42rp](https://github.com/LibrePhotos/librephotos/security/advisories/GHSA-x465-w9j9-42rp)). ExifTool tag names in a user's own date and burst detection rules could do the same in the exif service ([GHSA-cgq8-jvp9-r3j7](https://github.com/LibrePhotos/librephotos/security/advisories/GHSA-cgq8-jvp9-r3j7)). On the unified image and the Windows standalone build, a crafted `/media/` URL could read files outside the media folder ([GHSA-cf3f-2fmg-mjj6](https://github.com/LibrePhotos/librephotos/security/advisories/GHSA-cf3f-2fmg-mjj6)). Thumbnails kept the original photo's GPS position and camera details, so public links leaked the location even with "Share location information" off ([GHSA-j84j-mc98-7wq3](https://github.com/LibrePhotos/librephotos/security/advisories/GHSA-j84j-mc98-7wq3)). Nextcloud server addresses are now validated on the host the connection really uses, which closes a bypass of the check added in 1.2.0 ([GHSA-xq77-cj4c-42qr](https://github.com/LibrePhotos/librephotos/security/advisories/GHSA-xq77-cj4c-42qr)). The advisory for the album and `select_all` owner scope fix that shipped in 1.2.0 is published too ([GHSA-phvg-g65q-rhq3](https://github.com/LibrePhotos/librephotos/security/advisories/GHSA-phvg-g65q-rhq3)). Thanks to [wk-cs](https://github.com/wk-cs), [Seven11Eleven](https://github.com/Seven11Eleven), and [dotanm](https://github.com/dotanm) for the responsible disclosure.
